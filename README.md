# السعودية بالأرقام 🇸🇦

تحدٍّ عربي من ثلاثة أسئلة لبوث نادي علوم البيانات — جامعة جدة، مع إحصاءات المشاركات وتصويت وبطاقة تذكارية PDF. الواجهة React وTypeScript، والاستضافة Cloudflare Workers مع D1. يعمل التحدي دون حساب أو اسم أو بريد.

## التشغيل محليًا

روابط النسخة المنشورة:

- [التجربة — بيانات منفصلة](https://saudi-by-numbers-staging.saudi-by-numbers.workers.dev)
- [الموقع الأساسي](https://saudi-by-numbers.saudi-by-numbers.workers.dev)
- [شاشة البوث](https://saudi-by-numbers.saudi-by-numbers.workers.dev/results?display=1)
- [المصدر على GitHub](https://github.com/AhmedBahathiq/saudi-by-numbers)

يلزم Node.js 24 أو أحدث وnpm. نفّذ داخل مجلد المشروع:

```sh
npm ci
npm run db:local
npm run dev
```

افتح `http://localhost:8787`. هذه بيئة staging وقاعدة بياناتها محلية. لإعادة بناء الواجهة بعد التعديل شغّل `npm run build` ثم حدّث المتصفح؛ الخدمة تعيد تحميل كود Worker تلقائيًا.

## المسارات

- `/` بدء التحدي أو استكمال الجولة الحالية.
- `/quiz` الأسئلة بالترتيب: سهل، متوسط، رسم.
- `/result` الدرجة والبطاقة والتصويت الاختياري.
- `/results` إحصاءات المشاركات وتوزيع اختيارات الأسئلة.
- `/results?display=1` وضع شاشة البوث، تحديث كل خمس ثوانٍ.

الموقع يختار ثلاث مجالات مختلفة للجولة. الأسئلة والإجابات الصحيحة محفوظة على الخادم، ولا يرسل التفسير والحل إلى متصفح المشارك إلا بعد تأكيد الإجابة. المستودع مفتوح المصدر، لذا المسابقة نشاط تعليمي وليست اختبارًا محميًا من الاطلاع على الحلول عبر الكود.

## النشر الأول على Cloudflare

```sh
npx wrangler login
npx wrangler d1 create saudi-by-numbers-production
npx wrangler d1 create saudi-by-numbers-staging
```

أضف `database_id` الذي تعيده كل عملية إلى الربط المطابق في `wrangler.jsonc`. لا تضع رمز حساب أو API token في هذا الملف. لكل بيئة قاعدة منفصلة.

```sh
npx wrangler d1 migrations apply DB --remote --env staging
npm run build
npx wrangler deploy --env staging
```

راجع النسخة التجريبية، ثم:

```sh
npx wrangler d1 migrations apply DB --remote
npm run deploy
npm run qr -- https://YOUR-VERIFIED-WORKER.workers.dev
```

أداة QR تتحقق من استجابة الإنتاج قبل إنشاء PNG وSVG في `exports/`. رابط الإنتاج الفعلي يرجع من Wrangler؛ لا تفترض رابطًا قبل النشر.

## GitHub والنشر التلقائي

المستودع عام باسم `saudi-by-numbers` برخصة MIT. سير العمل `.github/workflows/deploy.yml` يختبر ويبني عند طلبات الدمج وتحديث `main`. مهمة النشر مشروطة بمتغير المستودع `CLOUDFLARE_ACTIONS_DEPLOY=true`، وعند تفعيلها تطبّق ترحيلات الإنتاج وتنشر بعد نجاح التحقق. تتطلب أسرار المستودع أو بيئة `production` في GitHub:

- `CLOUDFLARE_ACCOUNT_ID`
- `CLOUDFLARE_API_TOKEN` بصلاحيات نشر Workers، ورفع الأصول، وتعديل D1 للحساب المطلوب.

تم إعداد الأسرار ومتغير التفعيل في هذا المستودع. مفتاح النشر المخصص لحساب clubs ينتهي في ٢٥ ديسمبر ٢٠٢٦؛ يُستبدل في سر `CLOUDFLARE_API_TOKEN` قبل ذلك لاستمرار التحديثات. لا يؤدي انتهاء المفتاح إلى توقف الموقع المنشور. إذا نسخت المشروع إلى حساب آخر فأنشئ قواعدك ومعرّفاتك وأسرارك الخاصة.

## التشغيل يوم الفعالية

1. تأكد من مراجعة [بنك الأسئلة](docs/QUESTION_BANK.md) وعمل مصادره.
2. افتح رابط الإنتاج على جوال خارج حساب المشغّل، وأكمل جولة وتحقق من PDF.
3. افتح `/results?display=1` على شاشة البوث، واضغط وضع الشاشة لملء الشاشة.
4. اطبع QR الإنتاج بعد التحقق من الرابط. وفّر اتصال إنترنت للشاشة؛ المشاركة من جوال الزائر ممكنة من أي مكان.
5. لا تستخدم بيانات اختبارات الحمل في الإنتاج. استخدم staging للتجربة.
6. عند تعطل الإنترنت تبقى اختيارات الجولة مؤقتًا في نفس تبويب المتصفح. لا يظهر نجاح الحفظ إلا بعد رد الخادم. يمكن إعادة المحاولة دون مضاعفة النتيجة.
7. آخر اليوم صدّر CSV، واحتفظ به في مساحة خاصة بالنادي.

لإيقاف إنشاء جولات جديدة غيّر `ACCEPTING` في إعدادات الإنتاج إلى `"false"` وأعد النشر. يظل بإمكان الجولات القائمة إكمال الإجابات والتصويت وتظل النتائج متاحة. لتغيير الفعالية استخدم قيمة `EVENT_ID` جديدة؛ لا تمسح بيانات فعالية قائمة.

## تصدير CSV

```sh
npm run export
npm run export -- --staging --local
```

التصدير يتطلب اتصال Wrangler المصرّح به ويحتوي فقط على الجولات المكتملة، مع معرف مجهول والوقت والدرجة والأسئلة والخيارات والتصويت. ترقيم الاختيارات في CSV يبدأ من ١. ملفات `exports/` مستبعدة من Git. لا توجد واجهة تصدير عامة للزوار.

## الاختبارات والحدود

```sh
npm test
npm run test:integration
npm run test:load
```

آخر أمرين يستخدمان الخدمة المحلية افتراضيًا. اختبار الحمل افتراضيًا ١٠ آلاف جولة عند تزامن ٢٠٠ محليًا؛ يرفض بيئة الإنتاج. لاختبار staging المنشورة يجب تعيين `TEST_BASE_URL` و`ALLOW_STAGING_TEST=yes` و`LOAD_ROUNDS` إلى عدد لا يتجاوز ١٠٠٠. تعيّن `LOAD_CONCURRENCY` مستوى التزامن. التقارير تكتب في `test-results/` المستبعدة من Git. نجحت موجة منشورة من ٢٠٠ جولة متزامنة بلا أخطاء، ولا تضمن سعة مستمرة أو كفاية حدود الحساب.

كل إجابة تُحفظ بمفتاح فريد داخل قاعدة البيانات. المشغلات تحدث المجاميع عند أول إدخال فقط، وتحسب الجولة المكتملة مرة واحدة. صفحة النتائج تقرأ جداول صغيرة، مع تخزين مؤقت لخمس ثوانٍ؛ الجوال يحدّث كل ٣٠ ثانية أثناء ظهور الصفحة، والشاشة كل خمس ثوانٍ.

١٠ آلاف جولة كاملة مع التصويت تنتج قرابة ٥٠ ألف طلب كتابة HTTP، وعدد عمليات كتابة صفوف D1 أكبر بسبب المجاميع والفهارس. لا تفترض كفاية الخطة المجانية: راجع حدود Workers وD1 الفعلية قبل الفعالية واختر خطة مناسبة. لم يفعّل المشروع اشتراكًا مدفوعًا تلقائيًا.

## البيانات والمصادر

ملف `worker/questions.ts` هو مصدر الأسئلة. لتحديث النسخة، عدّل الأسئلة وارفع `BANK_VERSION` وشغّل `npx tsx scripts/question-bank.ts` ثم الاختبارات والبناء. لا تغيّر معنى سؤال قائم بنفس `id`؛ استخدم معرفًا جديدًا. كل جولة تحتفظ بنسخة من أسئلتها حتى لا يغيّر تحديث المحتوى تصحيح جولة جارية.

العدّاد يحسب الجولات المكتملة وليس الأشخاص الفريدين. يمكن إعادة اللعب والتصويت في كل جولة. التصويت عينة ذاتية من المشاركين، ولا يمثل جميع السكان أو الطلاب. إحصاءات الأسئلة تشمل جميع الإجابات المؤكدة حتى من الجولات غير المكتملة؛ الدرجات ومتوسطها يخصان المكتملة فقط. لا يظهر وصف السؤال الأكثر تحديًا إلا بعد خمس إجابات عليه، وهو وصف لهذه العينة.

لا يطلب التطبيق اسمًا أو بريدًا أو رقم هاتف، ولا يحفظ IP في D1. يحتفظ تبويب المتصفح بمفتاح جولة عشوائي واختيار غير مرسل لاستكمال التجربة. قد تحتفظ منصة الاستضافة بسجلات تشغيلها وفق إعداداتها وسياساتها. التطبيق لا يثبت هوية المشارك ولا يمنع الإعادة المتعمدة؛ يمنع احتساب إعادة إرسال الطلب نفسه.
